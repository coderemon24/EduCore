# No-Slop UI Design Protocol

When executing frontend engineering, designing layouts, or styling interfaces, you must strictly follow these structural and aesthetic rules to avoid generic AI-generated defaults.

## 🛑 Banned AI Slop Aesthetics
- **No Cliché Gradients:** Do not use primary purple-to-blue or pink-to-orange gradients on text, buttons, or card borders.
- **No Floating Glassmorphism:** Avoid overusing heavily blurred `backdrop-filter: blur()`, glowing translucent backgrounds, or rainbow neon border shadows unless explicitly requested.
- **No Arbitrary "Eyebrow" Labels:** Do not stack tiny all-caps text with excessive letter-spacing directly above every single heading (e.g., "FEATURE // WELCOME").
- **No Meaningless Sparkle Icons:** Do not use `✨` or custom sparkle SVG icons next to text to denote "smart" or "premium" features.
- **No Massive Border Radii:** Avoid nesting sharp inner elements inside hyper-rounded pill cards (e.g., matching `border-radius: 32px` on everything).

## ✅ Required Human-Crafted Standards
- **Authentic Typography:** Prioritize strict, highly-disciplined system font stacks (like Inter, SF Pro, or Roboto) with high contrast and explicit, intentional `line-height` ratios.
- **High-Information Density:** Design for utility. Avoid massive, vacuous hero sections with 120px padding that contain only 4 words. 
- **Solid Layout Architecture:** Build grid structures with crisp, solid borders (e.g., `border: 1px solid var(--gray-200)`) instead of nebulous, unaligned shadow drops.
- **Functional Interactive States:** Ensure buttons and interactive components use direct background state changes on `:hover` and `:active` rather than complex 3D scale transforms.

## 🎯 Pre-Delivery Checklist
Before marking this UI artifact as complete, verify:
1. Does this look like an automated template or a custom, bespoke product?
2. Are the color choices anchored to a specific brand palette instead of a generic statistical average?
3. Is there a logical layout grid keeping components strict?
